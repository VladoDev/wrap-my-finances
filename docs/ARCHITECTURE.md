# Architecture

## Overview

Feature-first Clean Architecture. The codebase is divided by feature rather than by technical
layer; each feature owns an independent Domain, Data, and Presentation layer.

## Dependency rule

Dependencies point inward, always:

```
Presentation  ──▶  Domain  ◀──  Data
```

Concretely, and enforced in code review:

- **`domain/` imports nothing from Flutter, Firebase, or `data/`.** No `package:flutter/*`, no
  `cloud_firestore`, no `json_serializable`. A domain entity must be constructible in a pure Dart
  unit test with zero setup. This is the single rule that makes the layering worth its cost.
- **`data/` depends on `domain/`** and implements the repository interfaces declared there.
- **`presentation/` depends on `domain/`** and never imports `data/` — not the models, not the
  data sources.
- **Features never import each other's internals.** If `wrapped` needs expenses, it depends on
  `expenses/domain`, and only on the abstract repository.
- **`core/` depends on nothing in `features/`.**

them later costs a refactor.

## Data flow: logging an expense

```
KeypadPage
   └─▶ ExpenseEntryController (Riverpod)
          └─▶ LogExpense use case
                 └─▶ ExpenseRepository (abstract, domain)
                        └─▶ ExpenseRepositoryImpl (data)
                               └─▶ ExpenseRemoteDataSource
                                      └─▶ FirebaseFirestore  ──▶ local cache (sync)
                                                             └─▶ server (async, background)
```

The controller returns as soon as the write hits the local cache. It never awaits the server
acknowledgement. See TECH_STACK.md § Offline strategy.

## Error handling

No exception crosses a layer boundary. Data sources catch `FirebaseException` and translate it
into a `Failure`; repositories return `Result<T>`; use cases propagate it; controllers map
`Failure` to UI state.

```dart
@freezed
sealed class Failure with _$Failure {
  const factory Failure.network() = NetworkFailure;
  const factory Failure.permissionDenied() = PermissionDeniedFailure;
  const factory Failure.notFound() = NotFoundFailure;
  const factory Failure.validation(String field) = ValidationFailure;
  const factory Failure.unknown(Object error, StackTrace stackTrace) = UnknownFailure;
}
```

`UnknownFailure` is the only variant that reports to Crashlytics. A user going through a tunnel
is not a crash and must not degrade the crash-free-users metric.

Because the app is offline-first, `NetworkFailure` is almost never surfaced on the logging path —
the write succeeds locally regardless. It matters only for operations that genuinely require the
server, such as account linking.

## Dependency injection and environment

`configureDependencies(AppEnvironment env)` is called from `bootstrap()` after
`Firebase.initializeApp`. The environment is registered as a singleton so any layer can read
configuration without a global:

```dart
@InjectableInit()
Future<void> configureDependencies(AppEnvironment env) async {
  getIt.registerSingleton<AppEnvironment>(env);
  await getIt.init();
}
```

Environment-dependent registrations use `@Environment` or a factory that reads
`getIt<AppEnvironment>()` — for example, a no-op `AnalyticsService` when running against
emulators.

## Routing

`go_router` with a small, flat route table. The initial route is always the keypad; there is no
splash route and no auth gate. Anonymous sign-in resolves during `bootstrap()`, in parallel with
the first frame, and the keypad is interactive before it completes.

If sign-in has not resolved when the user taps a category, the expense is buffered in memory and
flushed the moment the UID is available. The user never sees a spinner. This is the one piece of
genuine complexity the 3-second rule buys, and it belongs in `LogExpense`, not in the widget.

## Testing structure

`test/` mirrors `lib/` file for file. Every use case has a unit test; every repository has a test
against `fake_cloud_firestore`; the design system has golden tests; Security Rules have their own
suite run against the emulator.
